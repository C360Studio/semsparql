# Task 4.1 Notes — `reader.NATSRPCReader` and `cmd/semsparql`

## Implementation choices

1. **Query subjects from `graph.QueryVerbs()` and `graph.NewExactEntityReader`:**
   - `reader.NATSRPCReader` (`reader/nats.go`) never spells a `graph.ingest.query.*` subject literal. `NewNATSRPCReader`
     resolves the `batch` and `prefix` subjects from `graph.QueryVerbs()` and delegates exact single-entity reads to
     `graph.NewExactEntityReader(requester, timeout)`, mapping a classified `errs.ErrorNotFound` with code
     `graph.ErrorCodeEntityNotFound` to `errors.Join(ErrEntityNotFound, err)` so callers can check both
     `errors.Is(err, reader.ErrEntityNotFound)` and the underlying `*errs.ClassifiedError`.
   - `GetBatch` chunks requests (`defaultBatchChunkSize = 64`), adaptively splits chunks in half on classified
     `response_too_large` (reclassifying a 1-entity `response_too_large` as `errs.ErrorTransient`), and validates every
     response against ADR-084 via `graph.ClassifyStateContractError`.
   - `TestNATSRPCReaderNoLiteralQuerySubjectsInSource` parses all non-test Go files across `reader/`, `cmd/semsparql/`,
     `server/`, `sparql/`, and `irimap/` via `go/ast` and fails if any string literal contains `graph.ingest.query` or
     `graph.mutation`.

2. **Opaque cursor pagination, short-page continuation, and fail-closed selector verification (`scanPages`):**
   - `ScanPrefix` and `ScanPattern` send `graph.PrefixQueryRequest` over the declared `prefix` verb with
     `Limit: min(remaining+1, graph.MaxPrefixQueryLimit)` and follow `resp.NextCursor` until `resp.NextCursor == ""`.
   - A page with `len(resp.Entities) < req.Limit` and a non-empty `resp.NextCursor` is never treated as exhaustion
     (`graph-ingest`'s `marshalFittingPrefixPage` trims pages by byte budget when the serialized page approaches the
     broker's `max_payload`).
   - If a server returns an entity ID that does not match the requested `Prefix` or `Pattern`, `scanPages` fails closed
     with `ErrPatternCapabilityUnsupported` (`errs.ErrorFatal`) rather than falling back to client-side filtering. If
     `resp.NextCursor == cursor`, `scanPages` fails closed with `errs.ErrorFatal` (`pagination cursor did not advance`).

3. **Startup pattern capability check (`VerifyPatternCapability`):**
   - Implements the D.2 `TestProbeServerPatternCapabilitySeam` check: sends a negative probe
     `PrefixQueryRequest{Pattern: "invalid", Limit: 1}` (expecting classified `errs.ErrorInvalid` with code
     `types.ErrorCodeEntityIDPatternInvalid`) followed by a positive probe
     `PrefixQueryRequest{Pattern: "*.*.*.*.*.*", Limit: 1}`. If the negative probe succeeds (`err == nil`, as on a
     pre-`#259` responder that ignores the `"pattern"` field), `VerifyPatternCapability` returns
     `ErrPatternCapabilityUnsupported`, while transient/transport errors pass through directly without being misclassified.

4. **`cmd/semsparql` CLI and HTTP classified error mapping:**
   - `cmd/semsparql/main.go` validates flags, checks non-local bind protection (`-bearer-token`,
     `SEMSPARQL_BEARER_TOKEN`, or mTLS `-tls-cert`/`-tls-key`/`-tls-client-ca`), registers `packs.RegisterBFOCCOCore()`
     and `diekm.Register()`, runs `sparql.ValidateSuperclassClosure()`, connects `natsclient.Client` with
     `WithHealthInterval(0)` (retaining default runtime reconnects after `Connect(ctx)` succeeds), verifies server
     pattern capability via `natsReader.VerifyPatternCapability(ctx)` before opening the HTTP listener, and shuts down
     both HTTP and NATS with bounded contexts derived via `context.WithoutCancel(ctx)`.
   - `server.Server.writeExecutionError` maps `errs.IsTransient(err)`, `natsclient.IsNoResponders(err)`,
     `context.Canceled`, and `response_too_large` to HTTP `503 Service Unavailable` (with `Retry-After: 1`) and
     `errs.IsFatal(err)` to HTTP `500 Internal Server Error`, preserving `ClassifiedError.Class`, `Code`, and `Detail`
     in the JSON error response.
