# Task 3.2 developer notes — complete-chain folding and equivalent fallback evaluation

## Implementation choices

1. **Complete-chain `ProjectionSpec` detection and isolation analysis (`sparql/folding.go`):**
   - `FoldProjections(bgp, externalReferencedVars)` indexes all registered `vocabulary.ProjectionSpec` entries across
     `vocabulary.ListRegisteredPredicates()` and searches for candidate chains in a `BGPPattern` whose link predicates
     match `Steps[0..N-1].PredicateIRI`, whose intermediate node variables carry every declared non-empty
     `Steps[i].NodeClassIRI` constraint (`?n_i a <NodeClassIRI>` or `?n_i rdf:type/rdfs:subClassOf* <NodeClassIRI>`),
     and whose terminal triple `(n_{N-1}, <ValuePredicateIRI>, valueTerm)` matches `spec.ValuePredicateIRI`.
   - Folding requires strict intermediate-variable isolation:
     - Every intermediate variable `?n_0 .. ?n_{N-1}` must be a distinct `TermVariable` (and distinct from the root
       subject and terminal value terms if those are variables).
     - The total number of triple patterns in the BGP that mention `?n_i` in any position (subject, predicate, or
       object) must equal the exact number of triples consumed by the chain for `?n_i` (`2` for incoming step +
       outgoing step/value, plus `1` if `Steps[i].NodeClassIRI != ""`). Any extra triple pattern on `?n_i`—or any
       reference to `?n_i` in a BGP `FILTER` or an enclosing `OPTIONAL`/`UNION`/outer `FILTER` passed via
       `externalReferencedVars` (excluding `SELECT` projection variables, which are permitted)—disables folding for that
       chain so the query evaluates over the virtual unfolded graph instead.
     - Variable-predicate triple patterns (`?s ?p ?o`) never participate in chain folding.
   - When multiple registered predicates share an identical `ProjectionSpec` signature (`Steps` + `ValuePredicateIRI`),
     `FoldedChain.Predicates` records the sorted deduplicated union of all matching dotted predicates so folded
     evaluation unions every candidate predicate.

2. **Planner integration and fallback candidate lookup (`sparql/planner.go`):**
   - `PlanBGPWithScope` invokes `FoldProjections(bgp, nil)` and converts each `FoldedChain` into a `PlanStep` with
     `Folded != nil` (`AccessExactEntity` when the root subject is a bound entity IRI or a variable already bound by an
     earlier step such as `?entity a diekm:IntelligenceObservation`, or `AccessPredicate` over `Folded.Predicates` when
     the root subject is unbound).
   - For unfolded or partial-chain triples that remain in `RemainingTriples`, `LookupPredicateCandidates(predIRI)`
     returns the sorted union of flat `vocabulary.LookupPredicatesByIRI(predIRI)` matches and any projected dotted
     predicates whose `Steps[i].PredicateIRI` or `ValuePredicateIRI` equals `predIRI`. Similarly, when `?node a <C>` or
     `?node rdf:type/rdfs:subClassOf* <C>` matches a class `<C>` that is only used as an intermediate `NodeClassIRI` in
     a `ProjectionSpec` (and has no registered entity-ID `<domain>.<type>` pattern), `planTripleStep` falls back to
     `AccessPredicate` over `ProjectionPredicatesForNodeClass(C)` rather than requiring a full entity scan unless an
     entity-type pattern is also present.

3. **Folded evaluation, deterministic blank-node binding, and virtual unfolded fallback (`sparql/executor.go`):**
   - `evalFoldedChain` evaluates a `FoldedChain` directly against stored entity triples (`AccessExactEntity` via
     `GetEntity` when the root subject is bound, or `EntitiesByPredicate` + `GetBatch` over `chain.Predicates` when
     unbound) without materializing intermediate blank-node triples.
   - For each stored source triple `(entityID, pred, obj)` whose `pred` is in `chain.Predicates`,
     `extractFoldedChainMatches` converts `obj` to its RDF term via `tripleObjectToRDFTerm`, computes the canonical
     N-Triples object token via `irimap.CanonicalNTriplesObject(e.baseIRI, tr.Predicate, tr.Object, tr.Datatype)`, and
     binds each intermediate variable `chain.IntermediateVars[stepIdx]` to
     `RDFTerm{Kind: TermBlankNode, Value: irimap.BlankNodeID(entityID, tr.Predicate, canonObj, stepIdx)}` (`0`-based
     `stepIdx`).
   - To preserve exact mathematical RDF graph-set semantics when multiple dotted predicates on the same entity share a
     `ProjectionSpec` (or when duplicate stored triples exist), `extractFoldedChainMatches` deduplicates identical
     `(intermediate blank nodes, terminal RDF value)` tuples per entity: distinct source predicates produce distinct
     `BlankNodeID`s (because `predicate` is part of the `BlankNodeID` SHA-256 input) and therefore preserve their
     distinct solution bindings in `SELECT ?entity ?val` (unless `DISTINCT` is requested), while duplicate identical
     tuples on the same entity are deduplicated as a graph set.
   - When a query does not fold (partial chain, missing `NodeClassIRI` constraint, extra constraint/`FILTER` on an
     intermediate blank node, or variable predicate `?s ?p ?o`), `entityToRDFTriples` unfolds any stored triple whose
     dotted predicate has a non-empty `ProjectionSpec` into its virtual blank-node chain (`(s, step_0, _:b_0)`,
     optional `(_:b_i, rdf:type, NodeClassIRI)`, `(_:b_i, step_{i+1}, _:b_{i+1})`, and terminal
     `(_:b_{N-1}, ValuePredicateIRI, val)`) inside the per-entity deduplicated `rdfTriple` set. When an earlier triple
     binds a subject variable to a blank node `_:b_...`, `evalBoundSubjectPattern` resolves the blank node against the
     candidate entity graph so subsequent triples on that blank node evaluate without calling `Mapper.IRIToEntityID` on
     `_:b_...`.

## Verification, generated-check record, and mutation evidence

- **Proving tests (`sparql/folding_test.go`):**
  - `TestBGPFoldingCollapsesDIEKMChains`: registers the released `semvocab` DIEKM pack (`diekm.Register()`) and proves:
    1. Complete 1-step `intel.role.assigned` (`cco:ont00001967` -> `a obo:BFO_0000023` -> `cco:ont00001765`) and
       complete 3-step `intel.measurement.altitude-m` (`obo:BFO_0000056` -> `a cco:ont00000433` -> `obo:RO_0010002` ->
       `a cco:ont00001163` -> `cco:ont00001938` -> `a cco:ont00001202` -> `cco:ont00001863`) fold into a single
       `FoldedChain` step (`len(FoldProjections.Chains) == 1, len(RemainingTriples) == 0`), perform zero fallback blank-
       node scans, bind intermediate variables (`?role`, `?mice`, `?ice`, `?mcontent`) to deterministic
       `irimap.BlankNodeID(entityID, pred, canonObj, stepIdx)` values when projected in `SELECT`, and produce solution
       multisets identical to an independently materialized unfolded graph oracle (`materializeUnfoldedGraph` +
       `evalOverMaterializedOracle`) across multi-valued source triples (`1500.5` and `1825.0`).
    2. Partial chains (omitting terminal step 2 or starting at intermediate step 1) and chains missing a declared
       `NodeClassIRI` constraint (`?mice a cco:ont00000433` or `?role a obo:BFO_0000023`) do not fold
       (`len(FoldProjections.Chains) == 0`) and evaluate via the virtual unfolded graph to the exact same solutions as
       the materialized oracle.
    3. Extra triple constraints (`?role ?extraP ?extraO`) or `FILTER`s (`FILTER(isBlank(?role))`,
       `FILTER(STRSTARTS(STR(?role), "_:b_"))`) on intermediate variables disable folding and honor the constraint over
       the virtual unfolded graph.
    4. Variable-predicate queries (`SELECT ?s ?p ?o WHERE { ?s ?p ?o }`) never fold, return the complete unfolded RDF
       view (flat triples, virtual `rdf:type` triples, and unfolded blank-node chain triples) matching the materialized
       oracle, and fail with `ErrScanBudgetExceeded` when `WithMaxScanEntities` is exceeded.
    5. Ambiguous `ProjectionSpec` registrations (two distinct dotted predicates sharing the same `Steps` and
       `ValuePredicateIRI`) union all matching predicates and preserve both mathematical graph-set semantics and
       SPARQL solution-multiset multiplicity (`SELECT ?s ?val` vs `SELECT DISTINCT ?s ?val`).
