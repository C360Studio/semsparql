# Task 3.3 Implementation Notes: `CONSTRUCT`/`DESCRIBE`, Unfolding, and Export

## Decisions and Seams Implemented

1. **Unfolding and Terminal Datatype Propagation (`sparql/construct.go`):**
   - `UnfoldEntity(entity, baseIRI...)` materializes virtual `rdf:type` triples (`ClassIRI` and transitive
     `Superclasses`), unprojected stored triples (plus superclass `rdf:type` closure when a stored triple asserts
     `rdf:type`), and multi-step `ProjectionSpec` blank-node chains using
     `irimap.BlankNodeID(entityID, pred, canonObj, stepIdx)`.
   - Per D.2 probe `TestProbeTerminalDatatypePropagationSeam`, `propagateTerminalTriple` derives the terminal step's
     `(Object, Datatype)` from the exporter-owned canonical N-Triples object token of the normalized source triple:
     - Canonical entity IDs keep `Object: entityID` and `Datatype: message.EntityReferenceDatatype` (`"@id"`).
     - `xsd:integer`, `xsd:double`, and `xsd:boolean` literals without an explicit source `Datatype` hint convert to
       native `int64`, `float64`, and `bool` so `semengine/vocabulary/export` emits bare Turtle/JSON-LD numbers and
       booleans.
     - Explicit `xsd:dateTime`, `rdf:JSON`, and string literals that look like entity IDs, blank nodes, or
       `http(s)/urn:` IRIs set `Datatype` to the expanded datatype IRI so `export.Serialize` never misclassifies a
       string literal as an IRI resource or emits a relative pragmatic datatype IRI (`^^<datetime>`, `^^<float>`).
   - `ExportOptions(baseIRI)` registers any vocabulary prefixes from `vocabulary.ListRegisteredPrefixes()` into
     `semengine/vocabulary/export` via `export.RegisterPrefixes` and returns
     `[]export.Option{export.WithBaseIRI(base)}`.

2. **Loud Failure on Silent Exporter Omission (`sparql/construct.go`):**
   - Per D.2 probe `TestProbeSerializerInvalidTripleOmissionSeam`, `semengine/vocabulary/export.Serialize` silently
     skips triples with empty `Subject`, empty `Predicate`, `nil` `Object`, or `NaN`/`Inf` floats.
   - `ValidateTripleSerializable` and `ValidateGraphTriples` probe each output triple through
     `export.SerializeToString([]message.Triple{tr}, export.NTriples, ExportOptions(base)...)` and return
     `ErrInvalidOutputTriple` (`invalid_output_triple`) if any triple is empty, fails serialization, produces empty
     N-Triples output, or emits a non-IRI datatype token.

3. **`CONSTRUCT` and `DESCRIBE` Execution (`sparql/construct.go`, `sparql/executor.go`):**
   - `CONSTRUCT WHERE { ... }` and explicit `CONSTRUCT { ... } WHERE { ... }` instantiate template triples per solution
     row (skipping triples with unbound variables or literal subjects/predicates per SPARQL 1.1 §16.2).
   - When a `CONSTRUCT` template matches a wildcard `?s ?p ?o` over an entity or references a projected predicate's
     `StandardIRI`, `execConstruct` unfolds matching `ProjectionSpec` reification chains and virtual `rdf:type` triples;
     when a template projects a bound intermediate blank node `_:b_...`, `expandConstructBlankNodeChain` includes the
     reachable blank-node chain triples so exported subgraphs remain connected for SHACL validation.
   - Per owner ruling D.1d, `DESCRIBE` emits the outgoing entity Concise Bounded Description (CBD) for each target
     entity IRI (`UnfoldEntity`: stored outgoing triples + virtual `rdf:type` + unfolded blank-node chains); absent
     entity IRIs and non-entity IRIs contribute 0 triples without failing.
   - Per owner ruling D.1b, `MaxResults` counts deduplicated output RDF triples for `CONSTRUCT`, `DESCRIBE`, and
     `POST /export`, returning `ErrResultLimitExceeded` (`422 Unprocessable Entity`) by default or `200 OK` with
     `X-Semsparql-Truncated: true` and `X-Semsparql-Truncation-Reason: result_limit` when opted in.

4. **HTTP Graph Serialization, `GET /entities/{entity_id}.jsonld`, and `POST /export` (`server/`):**
   - `WriteGraphResult` validates all output triples via `sparql.ValidateGraphTriples` and delegates `FormatTurtle`,
     `FormatNTriples`, and `FormatJSONLD` serialization to
     `export.Serialize(w, triples, fmt, sparql.ExportOptions(baseIRI)...)`.
   - `GET /entities/{entity_id}.jsonld` validates `{entity_id}` with `message.ValidateEntityID` (`400 Bad Request` on
     invalid ID), fetches the entity via `GraphReader.GetEntity` (`404 Not Found` on `reader.ErrEntityNotFound`),
     unfolds via `sparql.UnfoldEntity`, and serializes `application/ld+json; charset=utf-8`.
   - `POST /export` enforces a `256 KiB` body cap (`DefaultMaxExportBytes`, returning `413 Content Too Large`), requires
     `Content-Type: application/json`, and accepts a JSON object with exactly one of `"prefix"` (validated via
     `semtypes.ValidateEntityIDPrefix`, no `*` wildcards) or `"construct"` (must parse as `sparql.QueryConstruct`),
     negotiating `text/turtle` (default), `application/n-triples`, or `application/ld+json`. `GET /export.ttl` is not
     registered (`404 Not Found`).
