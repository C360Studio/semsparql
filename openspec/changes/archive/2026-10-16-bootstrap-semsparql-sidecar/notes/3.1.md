# Task 3.1 developer notes — virtual `rdf:type` and subclass resolution

## Implementation choices

1. **Startup superclass ancestor-closure validation (`sparql/types.go`, `server/server.go`):**
   - `ValidateSuperclassClosure()` inspects all registered `EntityTypeMetadata` entries returned by
     `vocabulary.ListRegisteredEntityTypes()`. Because `vocabulary.RegisterEntityType` stores `Superclasses` as a flat
     slice and does not compute transitive closure across separately registered types, `ValidateSuperclassClosure()`
     checks every registered entity type `<domain>.<type>`: if any `sup` in `meta.Superclasses` is itself the
     `ClassIRI` of a registered entity type (via `vocabulary.LookupEntityTypesByClassIRI(sup)`), every ancestor `anc` in
     that superclass type's `Superclasses` must also be present in `meta.Superclasses`.
   - Any missing transitive ancestor returns a classified `*Error` wrapping `ErrIncompleteSuperclassClosure`
     (`ErrorCodeIncompleteSuperclassClosure = "incomplete_superclass_closure"`) naming the child entity type, the
     intermediate superclass IRI, and the missing ancestor IRI.
   - `server.New` calls `sparql.ValidateSuperclassClosure()` before constructing the server so incomplete vocabulary
     registrations fail loudly at startup.

2. **Bound and unbound virtual `rdf:type` and `rdf:type/rdfs:subClassOf*` resolution
   (`sparql/types.go`, `sparql/planner.go`, `sparql/executor.go`):**
   - `typeScanPatternsForClass(classIRI, org, platform)` calls `vocabulary.LookupEntityTypesByClassIRI(classIRI)` (which
     returns sorted `<domain>.<type>` keys whose `ClassIRI` or `Superclasses` match `classIRI`) and builds validated
     six-part entity-ID patterns `<org>.<platform>.*.<domain>.<type>.*` (substituting `*` when `org` or `platform` is
     empty or `*`).
   - `planBGPWithScope` classifies bound-class `?s a <C>` and `?s rdf:type/rdfs:subClassOf* <C>` patterns as
     `accessTypePattern` (rank ahead of `accessPredicate` and `accessFullScan`), storing the resolved
     `<org>.<platform>.*.<domain>.<type>.*` patterns on `planStep.Patterns`. When `?class` is bound earlier in the same
     BGP (for example via `?sub rdfs:subClassOf* <C>` before `?s a ?sub`), `reclassifyStepWithBoundVars` dynamically
     upgrades the step to `accessTypePattern` at execution time.
   - Per owner ruling B1 ([`#issuecomment-6224587243`](https://github.com/C360Studio/semsparql/issues/1#issuecomment-6224587243)),
     bound registered-class `?s a <C>` and `?s rdf:type/rdfs:subClassOf* <C>` execute `GraphReader.ScanPattern` only for
     the resolved `<org>.<platform>.*.<domain>.<type>.*` patterns (plus any registered projection node-class predicates
     when `<C>` is a `ProjectionSpec` `NodeClassIRI`) so non-matching entities never cross NATS.
   - `ResolveTypes(entityID)` parses the 6-part ID via `types.ParseEntityID(entityID)` using named fields
     (`eid.Domain + "." + eid.Type`), merges `vocabulary.LookupTypeIRIs(domainType)` and `"*"` wildcard types with
     `vocabulary.GetEntityTypeMetadata(domainType)`, and returns the deduplicated sorted set of `ClassIRI` (zero-length
     `rdfs:subClassOf*` step) plus all registered `Superclasses`.
   - `entityToRDFTriples` merges explicit stored `rdf:type` triples (`http://www.w3.org/1999/02/22-rdf-syntax-ns#type`)
     and virtual `rdf:type` triples as a mathematical RDF graph set (`seen map[rdfTriple]struct{}`), so an entity that
     both carries an explicit `rdf:type` triple and derives the same class IRI virtually emits that `(s, rdf:type, C)`
     triple exactly once.

3. **Standalone `?sub rdfs:subClassOf* ?sup` closure evaluation (`sparql/types.go`, `sparql/planner.go`, `sparql/executor.go`):**
   - Per owner ruling D.1c, standalone `rdfs:subClassOf*` patterns (not preceded by `rdf:type/`) evaluate over the
     finite registered ontology class graph in `vocabulary` (`ClassIRI` and `Superclasses` across
     `ListRegisteredEntityTypes()`) without invoking `GraphReader`.
   - `subClassClosurePairs()` collects all registered `ClassIRI` and `Superclasses` IRIs, emits reflexive `(C, C)` for
     every registered class/superclass IRI `C`, and computes the transitive closure of `(sub, sup)` pairs in
     deterministic lexicographical order. When a query binds either endpoint to an arbitrary IRI `<X>` not present in
     the vocabulary registry, `evalStandaloneSubClassStep` still satisfies the reflexive zero-length path `(<X>, <X>)`
     per SPARQL 1.1 property-path semantics.
   - The planner ranks standalone `rdfs:subClassOf*` steps ahead of `GraphReader` scans so joins such as
     `?s a ?sub . ?sub rdfs:subClassOf* obo:BFO_0000030` bind `?sub` in memory first and then execute targeted
     `ScanPattern` calls on `?s a ?sub`.
