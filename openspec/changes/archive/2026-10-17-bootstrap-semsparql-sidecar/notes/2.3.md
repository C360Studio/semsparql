# Task 2.3 developer notes — `/sparql` endpoint and MVP conformance

## Implementation choices

1. **Shared `/sparql` extraction and input byte bounding (`server/server.go`):**
   - `GET /sparql`, `POST /sparql` with `Content-Type: application/sparql-query`, and `POST /sparql` with
     `Content-Type: application/x-www-form-urlencoded` all converge on `extractSPARQLQuery` before calling
     `sparql.Parse` and `sparql.Executor.ExecuteQuery`.
   - `DefaultMaxQueryBytes` (`64 KiB` = 65,536 bytes, D.1b) bounds the decoded SPARQL query string across all three
     transports (`io.LimitReader(r.Body, maxBytes+1)` on raw POST, `io.LimitReader(r.Body, maxBytes*3+64+1)` prior to
     form decoding plus `len(q) > maxBytes` on `GET` and form `POST`), returning `413 Content Too Large`
     (`query_too_large`).
   - Named-graph protocol parameters (`default-graph-uri`, `named-graph-uri`) on `GET` or form `POST` return `400 Bad
     Request` with error code `unsupported_feature` naming `"named graphs"`.

2. **Query-form-aware `Accept` negotiation and W3C result serializers (`server/negotiate.go`):**
   - `NegotiateAccept(form, acceptHeader)` parses RFC 9110 `Accept` clauses with `q` weights, specificity
     (`type/subtype` > `type/*` > `*/*`), and explicit `q=0` exclusions. `SELECT` negotiates
     `application/sparql-results+json` (default), `application/sparql-results+xml`, `text/csv`, and
     `text/tab-separated-values`; `ASK` negotiates `application/sparql-results+json` (default) and
     `application/sparql-results+xml`.
   - Requesting an RDF graph format (`text/turtle`, `application/n-triples`, `application/ld+json`) on `SELECT` or
     `ASK`, requesting `text/csv` or `text/tab-separated-values` on `ASK`, or requesting a result table format on
     `CONSTRUCT` or `DESCRIBE` returns `406 Not Acceptable` (`ErrNotAcceptable`, D.1a).
   - `WriteSelectAskResult` buffers and serializes W3C SPARQL 1.1 JSON (`head.vars`, `results.bindings` with `uri`,
     `literal`, `xml:lang`, `datatype`, `bnode`, or `boolean`), XML (`http://www.w3.org/2005/sparql-results#`), CSV
     (RFC 4180 raw lexical values), and TSV (`?var` headers and N-Triples-formatted RDF terms) before writing headers so
     serialization errors never emit a partial `200 OK`.

3. **Deterministic budget status codes, opt-in truncation headers, and safe bind/lifecycle defaults (`server/server.go`):**
   - By default, `sparql.ErrResultLimitExceeded` and `sparql.ErrScanBudgetExceeded` map to `422 Unprocessable Entity`
     with JSON error code `sparql_result_limit_exceeded` or `sparql_scan_budget_exceeded`, and
     `sparql.ErrQueryTimeout` / `context.DeadlineExceeded` map to `504 Gateway Timeout` with `sparql_query_timeout`
     (D.1a).
   - When the request includes `X-Semsparql-Allow-Truncation: true`, the server passes `sparql.WithAllowTruncation(true)`
     to the executor and emits `200 OK` with `X-Semsparql-Truncated: true` and
     `X-Semsparql-Truncation-Reason: result_limit|scan_budget` when a result or scan cap is reached. Timeouts remain
     `504 Gateway Timeout`.
   - `ValidateConfig` defaults `BindAddress` to `127.0.0.1:8080` and refuses any non-loopback host (`0.0.0.0`, `::`, or
     non-local IP/hostname) with `ErrUnsafeExposure` unless `BearerToken` is non-empty (enforced with
     `subtle.ConstantTimeCompare`) or `TLSConfig` requires and verifies client certificates (`RequireAndVerifyClientCert`
     with non-nil `ClientCAs`).
   - `Serve(ctx, ln)` and `Shutdown(ctx)` refuse a `nil` context (`reader.ErrNilContext`) and drain in-flight requests
     on context cancellation without fixed timeouts.

## Verification, generated/fuzz check decisions, and mutation evidence

- **Proving tests (`server/server_test.go`):**
  - `TestSPARQL11ProtocolConformance`: verifies `GET /sparql`, raw `POST /sparql` (`application/sparql-query`), and form
    `POST /sparql` (`application/x-www-form-urlencoded`) across `SELECT` (JSON, XML, CSV, TSV) and `ASK` (JSON, XML),
    and verifies `406 Not Acceptable` when requesting graph formats on `SELECT`/`ASK` or CSV/TSV on `ASK`.
  - `TestUnsupportedFeatureErrors`: verifies HTTP `400 Bad Request` naming the unsupported feature across SPARQL Update,
    `SERVICE`, `GRAPH`, aggregates, `GROUP BY`, `HAVING`, subqueries, `VALUES`, `BIND`, `MINUS`, `SELECT REDUCED`,
    arbitrary property paths, and `default-graph-uri` / `named-graph-uri` protocol parameters.
  - `TestQueryLimits`: verifies `413 Content Too Large` on `> 64 KiB` queries (`GET`, raw `POST`, and form `POST`),
    `422 Unprocessable Entity` on `result_limit_exceeded` and `scan_budget_exceeded`, `200 OK` with
    `X-Semsparql-Truncated: true` and `X-Semsparql-Truncation-Reason` when `X-Semsparql-Allow-Truncation: true` is
    supplied, and `504 Gateway Timeout` (`query_timeout`) even when truncation is opted in.
  - `TestServerAuthAndBindValidation`: verifies default `127.0.0.1:8080` bind, refusal of non-local binds (`0.0.0.0`,
    `[::]`, `192.0.2.10`) without credentials (`ErrUnsafeExposure`), acceptance with `BearerToken` or mTLS
    `TLSConfig`, and `401 Unauthorized` (`WWW-Authenticate: Bearer`) when `BearerToken` is missing or mismatched.
  - `TestRequestCancellationAndServeLifecycle`: verifies in-flight request cancellation and `Serve(ctx, ln)` /
    `Shutdown(ctx)` lifecycle over an ephemeral `127.0.0.1:0` listener.
- **Generated / fuzz check decision:**
  - `FuzzSPARQLHTTPRequest` fuzzes external HTTP request inputs (`method`, `rawQuery`, `Content-Type`, `body`, `Accept`)
    with accepted and rejected seed classes. Bounded fuzz exploration (`go test -fuzz=^FuzzSPARQLHTTPRequest$
    -fuzztime=2s ./server`) executed 142,653 inputs across 12 workers with 0 failures after setting `req.URL.RawQuery`
    directly so unescaped spaces in fuzzed query strings reach `url.ParseQuery` inside the handler. Separate Rapid
    property generation is not duplicated in `server` because `NegotiateAccept` and status mappings are finite table
    functions while `sparql` query parsing and execution laws are already covered by Rapid in `sparql`.
- **In-tree mutation checks (with `cp` backup and verified SHA-256 restore):**
  - Mutant 1 (`server/server.go` `writeExecutionError` returning `http.StatusOK` instead of
    `http.StatusUnprocessableEntity` on `sparql.ErrResultLimitExceeded`): killed by
    `TestQueryLimits/result_limit_breach_returns_422_without_truncation_header_and_200_with_X-Semsparql-Truncated_on_opt-in`
    (restored SHA-256 `2db2508014ea69f275b1230b509bb4eb098806f8cb5ba50b8b3de6d807bc682d`).
  - Mutant 2 (`server/server.go` `ValidateConfig` returning `nil` instead of `ErrUnsafeExposure` on non-loopback bind
    without auth): killed by `TestServerAuthAndBindValidation` (restored SHA-256
    `2db2508014ea69f275b1230b509bb4eb098806f8cb5ba50b8b3de6d807bc682d`).
- **Statement coverage:** `92.1%` on `github.com/c360studio/semsparql/server` (threshold `80%`).
