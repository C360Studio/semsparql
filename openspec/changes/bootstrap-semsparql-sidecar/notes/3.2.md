# Task 3.2 developer notes — complete-chain folding and equivalent fallback evaluation

## Implementation choices

1. **Complete-chain `ProjectionSpec` detection and isolation analysis (`sparql/planner.go`):**
   - `foldProjections(bgp, externalReferencedVars)` indexes all registered `vocabulary.ProjectionSpec` entries across
     `vocabulary.ListRegisteredPredicates()` and searches for candidate chains in a `BGPPattern` whose link predicates
     match `Steps[0..N-1].PredicateIRI`, whose intermediate node variables carry every declared non-empty
     `Steps[i].NodeClassIRI` constraint (`?n_i a <NodeClassIRI>` or `?n_i rdf:type/rdfs:subClassOf* <NodeClassIRI>`),
     and whose terminal triple `(n_{N-1}, <ValuePredicateIRI>, valueTerm)` matches `spec.ValuePredicateIRI`.
   - Folding requires strict intermediate-variable isolation:
     - Every intermediate variable `?n_0 .. ?n_{N-1}` must be a distinct `TermVariable` (and distinct from the root
       subject and terminal value terms if those are variables).
     - The total number of triple patterns in the BGP that mention `?n_i` in any position (subject, predicate, or
       object) must equal the exact number of triples consumed by the chain for `?n_i` (`2` for incoming step +
       outgoing step/value, plus `1` if `Steps[i].NodeClassIRI != ""`). Any extra triple pattern on `?n_i`—or any
       reference to `?n_i` in a BGP `FILTER` or an enclosing `OPTIONAL`/`UNION`/outer `FILTER` passed via
       `externalReferencedVars` (excluding `SELECT` projection variables, which are permitted)—disables folding for that
       chain so the query evaluates over the virtual unfolded graph instead.
     - Variable-predicate triple patterns (`?s ?p ?o`) never participate in chain folding.
   - When multiple registered predicates share an identical `ProjectionSpec` signature (`Steps` + `ValuePredicateIRI`),
     `foldedChain.Predicates` records the sorted deduplicated union of all matching dotted predicates so folded
     evaluation unions every candidate predicate.

2. **Planner integration and fallback candidate lookup (`sparql/planner.go`):**
   - `planBGPWithScope` invokes `foldProjections(bgp, disallowedVars)` and converts each `foldedChain` into a `planStep`
     with `Folded != nil` (`accessExactEntity` when the root subject is a bound entity IRI or a variable already bound
     by an earlier step such as `?entity a diekm:IntelligencePlatform`, or `accessPredicate` over `Folded.Predicates`
     when the root subject is unbound).
   - For unfolded or partial-chain triples that remain in `RemainingTriples`, `lookupPredicateCandidates(predIRI)`
     returns the sorted union of flat `vocabulary.LookupByIRI(predIRI)` matches and any projected dotted predicates
     whose `Steps[i].PredicateIRI` or `ValuePredicateIRI` equals `predIRI`. Similarly, when `?node a <C>` or
     `?node rdf:type/rdfs:subClassOf* <C>` matches a class `<C>` that is used as an intermediate `NodeClassIRI` in a
     `ProjectionSpec`, `classifyTriplePattern` includes `projectionPredicatesForNodeClass(C)` so candidate entities are
     selected via `EntitiesByPredicate`.

3. **Folded evaluation, deterministic blank-node binding, and virtual unfolded fallback (`sparql/executor.go`):**
   - `evalFoldedStep` evaluates a `foldedChain` directly against stored entity triples (`accessExactEntity` via
     `GetEntity`/`GetBatch` when the root subject is bound, or `EntitiesByPredicate` over `chain.Predicates` when
     unbound) without materializing intermediate blank-node triples.
   - For each stored source triple `(entityID, pred, obj)` whose `pred` is in `chain.Predicates`, `evalFoldedStep`
     extracts the canonical N-Triples predicate and object token via
     `irimap.CanonicalNTriplesPredicateAndObject(tr, e.baseIRI)` and binds each intermediate variable
     `chain.IntermediateVars[stepIdx]` to
     `Term{Kind: TermBlankNode, Value: irimap.BlankNodeID(entityID, tr.Predicate, canonObj, stepIdx)}` (`0`-based
     `stepIdx`).
   - To preserve exact mathematical RDF graph-set semantics when multiple dotted predicates on the same entity share a
     `ProjectionSpec` (or when duplicate stored triples exist), `evalFoldedStep` deduplicates identical
     `(subject, intermediate blank nodes, terminal RDF value)` tuples per entity: distinct source predicates produce
     distinct `BlankNodeID`s (because `predicate` is part of the `BlankNodeID` SHA-256 input) and therefore preserve
     their distinct solution bindings in `SELECT ?entity ?val` (unless `DISTINCT` is requested), while duplicate
     identical tuples on the same entity are deduplicated as a graph set.
   - When a query does not fold (partial chain, missing `NodeClassIRI` constraint, extra constraint/`FILTER` on an
     intermediate blank node, or variable predicate `?s ?p ?o`), `entityToRDFTriples` unfolds any stored triple whose
     dotted predicate has a non-empty `ProjectionSpec` into its virtual blank-node chain (`(s, step_0, _:b_0)`,
     `(_:b_i, rdf:type, NodeClassIRI)` plus superclasses, `(_:b_i, step_{i+1}, _:b_{i+1})`, and terminal
     `(_:b_{N-1}, ValuePredicateIRI, val)`) inside the per-entity deduplicated `rdfTriple` set.

## Verification, generated-check record, and mutation evidence

- **Proving tests (`sparql/folding_test.go`):**
  - `TestBGPFoldingCollapsesDIEKMChains`: registers the released `semvocab` DIEKM pack (`diekm.Register()`) and proves:
    1. Complete 1-step `intel.role.assigned` (`obo:BFO_0000196` -> `a obo:BFO_0000023` -> `rdfs:label`) and complete
       3-step `intel.measurement.altitude-m` (`obo:BFO_0000196` -> `a cco:ont00000787` -> `cco:ont00001904` ->
       `a cco:ont00001163` -> `obo:BFO_0000084` -> `a cco:ont00000253` -> `diekm:altitudeMetersValue`) fold into a
       single `foldedChain` step (`len(foldProjections.Chains) == 1, len(Remaining) == 0`), perform zero fallback blank-
       node scans, bind intermediate variables (`?role`, `?altNode`, `?mice`, `?ibe`) to deterministic
       `irimap.BlankNodeID(entityID, pred, canonObj, stepIdx)` values when projected in `SELECT`, and produce solution
       multisets identical to an independently materialized unfolded graph oracle across multi-valued source triples
       (`1500.5` and `1825.0`).
    2. Partial chains (omitting terminal step 2 or starting at intermediate step 1) and chains missing a declared
       `NodeClassIRI` constraint (`?altNode a cco:ont00000787` or `?role a obo:BFO_0000023`) do not fold and evaluate
       via the virtual unfolded graph to the exact same solutions as the materialized oracle.
    3. Extra triple constraints (`?role ?extraP ?extraO`) or `FILTER`s (`FILTER(BOUND(?role))`,
       `FILTER(REGEX(STR(?role), "^_:b_"))`) on intermediate variables disable folding and honor the constraint over the
       virtual unfolded graph.
    4. Anchored variable-predicate queries (`SELECT ?s ?p ?o WHERE { ?s a diekm:IntelligencePlatform ; ?p ?o }`) never
       fold the `?p ?o` triple, return the complete unfolded RDF view matching the materialized oracle, and fail with
       `ErrScanBudgetExceeded` when `WithMaxScanEntities` is exceeded.
    5. Ambiguous `ProjectionSpec` registrations (two distinct dotted predicates sharing the same `Steps` and
       `ValuePredicateIRI`) union all matching predicates and preserve both mathematical graph-set semantics and
       SPARQL solution-multiset multiplicity (`SELECT ?s ?val` vs `SELECT DISTINCT ?s ?val`).
