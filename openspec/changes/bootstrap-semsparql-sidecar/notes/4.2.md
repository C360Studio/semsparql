# Task 4.2 Developer Notes — Live NATS/DIEKM End-to-End Integration Tests

- **`server/diekm_integration_test.go` (`//go:build integration`, `package server_test`)**:
  - `startDIEKMIntegrationFixture(t, maxPayload)` starts an in-process `nats-server/v2` with JetStream on an ephemeral
    loopback port (`127.0.0.1:-1`) and `MaxPayload: 4096`, registers the released SemVocab `packs.RegisterBFOCCOCore()`
    and `diekm.Register()` packs (`semvocab v0.1.0`) plus the two explicit test helper predicates (`rdf.syntax.type`
    mapped to `rdf:type` and `intel.platform.reported-by` with `Datatype: "entity_id"`), starts a real
    `graphingest.CreateGraphIngest` component (`semengine v0.1.0-alpha.2`), seeds 8 DIEKM UAV/observation/mission
    entities into JetStream KV `ENTITY_STATES`, captures baseline per-key KV revisions, subscribes to
    `graph.mutation.>` and `graph.ingest.query.>` on the live NATS broker, wires `reader.NATSRPCReader` +
    `sparql.Executor` + `server.Server` (`httptest.NewServer`), and builds a reference `reader.MemoryReader` +
    `server.Server` from the identical entity snapshot for independent oracle comparisons.
  - `TestIntegrationDIEKMEndToEndSuite` exercises all 11 issue #1 §3 proving tests end-to-end over HTTP ->
    `server.Server` -> `sparql.Executor` -> `reader.NATSRPCReader` -> NATS RPC (`graph.ingest.query.{entity,batch,prefix}`)
    -> `graph-ingest` -> JetStream KV `ENTITY_STATES`:
    1. `TestIRIMapperRoundTripAndBlankNodeIDMultiValued`
    2. `TestBGPFoldingCollapsesDIEKMChains`
    3. `TestLookupByIRIMultiMatchUnion`
    4. `TestVirtualRDFTypeAndSubclassResolution`
    5. `TestScanPatternReaderParity` (verifies multi-page opaque cursor pagination with `>= 3` `graph.ingest.query.prefix`
       NATS RPC requests under `MaxPayload: 4096`)
    6. `TestSuperclassClosureStartupCheck`
    7. `TestConstructUnfoldsReifiedGraphForSHACLAndTerminalDatatypes` (verifies `CONSTRUCT`, `DESCRIBE`,
       `GET /entities/{entity_id}.jsonld`, and `POST /export` across Turtle, N-Triples, and JSON-LD using independent
       RDF parsers `parseIndependentNTriples`, `parseIndependentTurtle`, and `parseIndependentJSONLD` with
       `json.Decoder.UseNumber()`)
    8. `TestSPARQL11ProtocolConformance`
    9. `TestQueryLimits`

    11. `TestZeroKVWritesAndZeroMutations` (asserts zero `graph.mutation.*` messages published and unchanged key set and

  - `TestPropIntegrationDIEKMLiveServerParity` runs 100 generated Rapid checks across `SELECT`, `ASK`, `CONSTRUCT`, and
    `DESCRIBE` queries over the live NATS `server.Server` and asserts exact parity with the reference `MemoryReader`
    `server.Server` plus zero NATS mutations.

## Implementation Choices Not Spelled Out in Design

1. **Stored explicit `rdf:type` predicate under `graph.MarshalEntityState`**:
   - Unlike in-memory `EntityState` fixtures, `graph.MarshalEntityState` validates that every stored `message.Triple`
     predicate obeys the 3-segment dotted predicate contract (`domain.category.property`). To test explicit stored
     `rdf:type` deduplication alongside virtual `rdf:type` over live `ENTITY_STATES` KV, the fixture registers
     `rdf.syntax.type` with `vocabulary.WithIRI(sparql.RDFTypeIRI)` and `Datatype: "iri"`.
2. **Sizing `MaxPayload: 4096` for both `GetBatch` and multi-page `ScanPattern`**:
   - Keeping the 3 UAV platform entities compact while padding the 5 observation entities
     (`strings.Repeat("diekm-telemetry-pad-", 45)`) allows `GetBatch` on the 3 UAV entities to fit within a single
     4096-byte NATS reply while `ScanPattern("*.*.*.*.*.*")` paginates across `>= 3` opaque cursor pages on
     `graph.ingest.query.prefix`.
3. **Preserving numeric lexical forms in `parseIndependentJSONLD`**:
   - Using `dec.UseNumber()` in the test's independent JSON-LD parser distinguishes integer JSON numbers (`4`, `1`) from
     floating-point numbers (`1500.5`, `320.25`) so `xsd:integer` and `xsd:double` canonicalize identically across
     Turtle, N-Triples, and JSON-LD.
